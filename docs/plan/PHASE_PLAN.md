# Phase 0 至 Phase 13 开发计划

依据：根目录《蛋糕店订单管理系统需求说明书_V1.1.docx》（实际修订 2026-11-24），以及用户 2026-11-24 确认的 ENV-01：Node.js 使用 24.20.0，原 DOCX 不改。本文为阶段规划，不代表任何后续阶段已授权、已实现或已通过测试。当前仅执行 Phase 0，完成文档后停止，等待用户审核并明确指定下一阶段。

## 通用执行与验收规则

1. 严格按 0→13 顺序，每次只执行用户明确指定阶段；前一阶段通过且用户授权是下一阶段的双重前提。前置问题没有解决时，记录受影响工作，不以自行扩范围绕过。
2. 各阶段先读 AGENTS.md、当前状态、相关源文件与调用关系、需求对应条目、Git 状态；发现已有工程先复用。当前无 Git 仓库，后续仍须复查，不能未经确认 git init；任何阶段均不自动 commit/push。
3. 下列允许目录只约束该阶段**未来授权后的**修改范围，当前不创建。实际包名前缀、文件名、依赖精确补丁在 Phase 1 确定；不得利用占位路径授权修改无关模块。
4. 每阶段可同步 PROJECT_STATUS.md、TODO.md 和本阶段 Markdown 报告；需求追踪文档仅更新实现/验证状态和证据，不擅改原始需求。README 只在启动、验证或交付方式实际变化时更新。原 DOCX 始终保护。
5. 新功能配套有意义的单测及权限/归属/异常集成测试，事务功能必须用真实 MySQL/InnoDB 测试并发与回滚。测试数据隔离，不能污染用户已有数据库；测试库创建/写入在相应阶段获授权后才进行。
6. 后续阶段后端计划使用 `mvn.cmd test` / `mvn.cmd verify`，前端计划使用 `npm.cmd run test` / `npm.cmd run build`；以实际已配置脚本为准，缺命令须先记录，不能声称已跑。集成测试纳入 verify 后才能用该命令作证据。Phase 0 不安装依赖、不跑构建。
7. 每份 reports/PHASE_N_REPORT.md 记录范围、实际文件、命令/版本/结果、需求编号、证据、失败/未执行原因、风险和验收结论；技术构建、真实接口、视觉验收、并发和整体验收分别记录，不能互相替代。
8. 总验收固定 20 功能、45 API、17 页面、46 场景、6 核心表。低优先级仍须交付。所有阶段必须遵守三角色权限、同店隔离、快照、时间、金额与状态字典，不擅增业务表或更改接口。
