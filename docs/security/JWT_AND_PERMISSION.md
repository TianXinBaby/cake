# Phase 3 JWT 与权限机制

日期：2026-11-25（Asia/Shanghai）。原文依据为 V1.1 的 3.7、5.1、5.4、API-01/11～14 和 DATA-09。本文与 [认证设计](AUTHENTICATION_DESIGN.md)、[密码安全](PASSWORD_SECURITY.md) 配套；历史测试和构建结论见 [Phase 3 报告](../../reports/PHASE_3_REPORT.md)，参数契约补充及本轮验证结论见 [Phase 3.1 报告](../../reports/PHASE_3_1_REPORT.md)。Phase 3.1 不修改 JWT、BCrypt、登录锁定或 tokenVersion 机制。

## 技术与密钥

沿用 Boot 3.5.16 的依赖管理，使用 `spring-boot-starter-security`、`spring-security-oauth2-jose` 提供的 Nimbus JWT 编解码器及 BCrypt。精确解析版本由现有Phase3依赖树和历史报告记录，本轮未升级已有 Spring Boot、MyBatis-Plus、MySQL 驱动或前端版本。

固定签名算法为 HS256，解码器只接受该算法。签名密钥从进程环境 `JWT_SECRET_BASE64` 读取，Base64 解码后至少 32 字节，部署时应由安全随机源生成并由外部受控配置注入。没有源码默认密钥、真实密钥配置、令牌表、黑名单表、Redis 或缓存服务。

密钥缺失、Base64 非法或长度不足时启动失败，提示配置要求，不输出输入值。测试使用运行时随机临时密钥，仅属于测试进程；测试密钥不用于初始化账号或生产部署。更换密钥会使原密钥签发的令牌不能验签，本阶段不提供密钥轮换 API。

## 令牌内容和两小时时间

| Claim | 内容与校验 |
| --- | --- |
| `sub` | 用户 ID 的正十进制字符串，范围不超过 BIGINT UNSIGNED |
| `role` | 签发时数据库角色，限定 ADMIN/MERCHANT/CUSTOMER；不能用它覆盖数据库当前角色 |
| `ver` | 签发时非负整数 token_version；每次保护请求与数据库当前值比较 |
| `iat` | 签发时间，JWT NumericDate 秒精度 |
| `exp` | `iat+7200秒`，严格两小时 |

签发采用服务端时钟，同一秒精度时刻同时用于 JWT 和响应 expiresAt。响应通过已有 Jackson 时间序列化转换为北京时间毫秒及 `+08:00`，例如 `2026-11-25T21:00:00.000+08:00`。JWT NumericDate 与外部 ISO 8601 展示格式不同，但代表同一截止时刻。

解码检查签名、固定算法、iat/exp 存在、签发时间不在未来、有效期恰好两小时；当前时间达到 exp 即过期，不设置额外宽限。非法 subject、角色、版本类型或超限值拒绝为 40102，不向客户端返回解析异常。merchantId 不作为可信 JWT 来源，绑定每次从数据库查询。

## 请求过滤顺序

请求日志关联过滤器在安全链前生成服务端 requestId；不采信客户端请求号。JWT 过滤器仅为明确的匿名注册和登录请求跳过认证。其他请求出现 Authorization 时校验单个 Bearer 头，不接受重复头、额外内容、Basic 或格式错误的令牌。缺失令牌时交给安全链对受保护接口返回 40102。

成功解码后读取 sys_user，依次确认用户存在、status=1、token_version 相同、当前角色有效，并核验商家绑定。认证成功才建立 SecurityContext，包含 userId、数据库当前 role、tokenVersion 和商家专属 merchantId。安全链不创建 HTTP Session，不启用表单登录、HTTP Basic、默认退出页或自动生成的应用账号。

每个保护请求都重新读取数据库；没有缓存导致禁用或版本更新延迟生效。本人写操作在事务内再次锁定账号并复核状态、版本，避免请求通过过滤器后与退出/改密竞争时使用旧版本完成修改。

## 角色入口

| 入口 | 权限基础 |
| --- | --- |
| `POST /api/auth/register`、`POST /api/auth/login` | 匿名 |
| 本人资料、改昵称、改密码、退出 | 三类已认证角色，仅本人 |
| 后续 `/api/admin/**` | 仅 ROLE_ADMIN，当前不实现商家/用户管理业务 |
| 后续 `/api/merchant/**` | 仅 ROLE_MERCHANT，后续资源查询仍须强制本店归属 |
| 后续 `/api/orders/**` | 仅 ROLE_CUSTOMER，后续订单查询仍须强制本人归属 |
| 原规划公开 GET 商家/商品/分类入口 | 保留匿名访问基础，本阶段不实现这些业务接口 |

路径角色校验只是基础设施，不代表后续接口已经实现、验收或获得开发授权。ADMIN 不因此获得本店经营接口权限；平台只在需求明确列出的后台接口跨店查询或维护。前端隐藏按钮、路由提示和本地 role 都不能替代后端校验。

## 版本失效与并发

登录成功携带当前版本，不增加版本。退出在本人行锁下原子加一版本；同账号此前签发的全部 JWT 均失效。修改密码将新 BCrypt 散列与版本加一写入同一条 SQL、同一事务；写入失败则整体回滚，不返回替代 JWT。后续平台启停 CUSTOMER 时仍需按原需求在同一事务更新状态与版本，该管理 API 不在本阶段。

相同旧版本的并发退出或密码修改会串行取得账号锁。首个有效操作提交版本变化后，后续旧身份复核失败为 40102；不能以最后写覆盖方式恢复旧密码或旧版本。数据库访问失败、死锁或版本 INT 上限导致更新失败均安全返回 50001，不静默溢出、不改变字段类型。

## 错误与日志

| HTTP / 业务码 | 对外含义 |
| --- | --- |
| 400 / 40001 | 参数错误；可定位真实字段时data.fieldErrors为字段名到字符串数组的对象，否则data=null |
| 401 / 40101 | 账号或密码错误，或改密原密码错误 |
| 401 / 40102 | 未登录、格式错误、过期、签名无效、用户不存在或版本失效 |
| 403 / 40301 | 数据库账号禁用 |
| 403 / 40302 | 角色不足或指定受保护字段 |
| 423 / 42301 | 临时锁定，data 含统一时间格式 lockedUntil |
| 500 / 50001 | 系统、数据库或账号绑定完整性故障，data 含 requestId |

仍采用统一 `code/msg/data`，不把异常转为 HTTP 200，不向客户端显示 SQL、密钥、密码散列、栈或内部异常。日志使用安全事件和服务端请求关联号，不打印完整 JWT、密码、请求体、数据库凭据或原始数据库异常。

Phase 3.1 已确认 `data.fieldErrors` 为 `Map<String, List<String>>`：实际 API 的 lowerCamelCase 字段名映射到字符串数组，允许多字段及同字段多消息。无法定位字段、只有未知字段或对象级错误时仍为 `data=null`，不创建 `_global` 或虚拟字段，不把内部变量名或snake_case列名当作API字段。尝试修改 `role/status/merchantId` 等受保护字段仍优先使用 HTTP 403/40302；认证失效、禁用、锁定和系统异常继续使用上表既有状态及结构，不附加参数错误字段。前端继续按原40102流程清理对应会话，不增加页面。

生产 TLS、外部密钥托管、真实浏览器业务页面和后续资源归属接口不由当前认证测试代替验收。测试范围及运行证据入口见 [认证 API 测试](AUTH_API_TESTS.md)。
