# Phase 3 密码与登录锁定安全

日期：2026-11-25（Asia/Shanghai）。依据 V1.1 的 USER-01/02/04、API-01/10/14、sys_user 字典和 5.4。本文件记录认证实现与边界；历史测试结果见 [Phase 3 报告](../../reports/PHASE_3_REPORT.md)，Phase 3.1 参数错误契约及本轮验证结果见 [Phase 3.1 报告](../../reports/PHASE_3_1_REPORT.md)。本轮不修改BCrypt配置、密码规则、登录锁定或tokenVersion机制。

## BCrypt 存储

使用 Spring Security `BCryptPasswordEncoder(10)`，工作因子满足原文至少 10 的要求。注册和修改密码均由服务端生成随机盐的 BCrypt 散列，保存到已有 `sys_user.password VARCHAR(100)`；验证使用 matches，不比较明文或重新编码后的字符串。

没有明文密码列、可逆加密、固定盐、默认弱密码或额外安全表。密码不返回到 User/登录响应，不进入 Pinia、浏览器存储、日志、SQL 模板、报告或异常提示。数据库现有字段和 CHECK 保持不变。

注册固定 CUSTOMER 并启用，不提供 ADMIN/MERCHANT 公开注册。ADMIN 初始化和后续平台创建商家同样应使用 BCrypt；当前保留 Phase 2 参数化初始化器，缺少外部安全参数时不创建真实初始化账号，不编造手机号或店铺资料。

## 输入规则

新密码必填，6～20 位可见非空白字符；不通过 trim 把非法密码变成另一段合法密码。校验拒绝空白、空格分隔符、控制字符、格式控制字符及未定义字符。修改密码时新密码不得与当前密码相同，通过 BCrypt matches 判定，不能通过散列字符串不同误判为密码不同。

登录和原密码输入必须提供字符串；格式错误参数使用 40001，合法输入但密码不正确使用 40101。登录账号按注册手机号识别，不接受客户端选择 role。

Phase 3.1 已确认参数错误为 HTTP 400/40001：能定位时，`data.fieldErrors` 使用实际API字段名到字符串数组的对象，例如 `{"fieldErrors":{"newPassword":["新密码长度必须为6到20个字符","新密码不能包含空白字符"]}}`。一次收集多字段及同字段多消息；登录为 `username/password`，改密为 `oldPassword/newPassword`，均为lowerCamelCase，不暴露内部变量名或数据库列名。无法定位、只有未知字段、JSON语法或对象级错误等继续 `data=null`，禁止 `_global` 或其他虚拟字段。受保护字段修改仍为40302，不能伪装成密码参数错误。

**Unicode 长度口径仍有边界：**当前密码长度采用 Java `String.length()` 的 UTF-16 代码单元计数，补充平面字符占两个代码单元；昵称则按 Unicode code point 计数。V1.1 只写“位可见字符”，没有进一步定义补充字符、组合字符或字素簇的长度口径，因此不能把当前规则称作所有 Unicode 可见字符场景均已确认。当前没有擅自增加 ASCII 或 72 字节公共业务限制；该边界在阶段报告中记录，后续规则变化须保持需求一致并有针对性测试。

## 登录失败与临时锁定

| 状态/动作 | 处理 |
| --- | --- |
| 账号不存在 | 使用虚拟 BCrypt 散列完成密码校验路径，返回统一 40101 |
| 账号 status=0 | 返回 40301，不签发 JWT |
| locked_until 晚于数据库当前时间 | 返回 42301 和 lockedUntil，不再增加次数 |
| 锁定期结束后的下一次尝试 | 以 0 为新周期起点，再判断此次密码 |
| 连续失败第 1～4 次 | 保存相应计数，返回 40101 |
| 连续失败第 5 次 | 保存计数 5、locked_until=数据库当前时间+10分钟，返回 42301 |
| 登录成功 | 清零计数、清空锁定、刷新数据库 update_time 后签发 JWT |

失败计数和锁定由同账号行锁保护，在事务中写入并提交后才向上层报告业务失败，避免业务异常把失败次数回滚。数据库时间来自 CURRENT_TIMESTAMP(3)，JDBC 会话为 +08:00；响应 lockedUntil 用统一 ISO 8601 毫秒 +08:00 格式。不同账号独立计数，锁定不改变 status，不等于永久停用。

不存在账号和错误密码使用完全相同的 HTTP 401、业务码 40101 和“账号或密码错误”，不在消息中泄露账号存在性。虚拟散列只用于计算，不对应真实账号或可登录凭据；这也不构成对所有网络计时侧信道已完全消除的声明。

## 修改密码与回滚

API-14 先以当前 JWT 获取本人身份，事务内锁定本人账号并重新核验启用状态和版本，然后校验旧密码与新旧不同。旧密码错误返回 40101，保持原认证异常结构；新密码格式不符或新旧相同返回 40001，错误定位到 `data.fieldErrors.newPassword` 的字符串数组，数据库数据保持原值。

成功时同一 SQL 更新 password、token_version=token_version+1 和 update_time=CURRENT_TIMESTAMP(3)，同事务提交；不返回散列、明文或新 JWT。所有已有旧 JWT 随即在下一次保护请求被拒绝，前端清理旧状态并要求重新登录。事务中任何写入错误必须回滚密码和版本，不能只完成其中一项。

并发修改密码依据账号行锁和事务内版本校验串行处理；旧身份不能在另一个请求已改密后再次覆盖。退出同样更新版本，行为详见 [JWT 与权限](JWT_AND_PERMISSION.md)。

## 测试与阶段边界

测试应验证散列能匹配原密码、不同盐、非明文、默认因子，失败 1～4 次、第 5 次锁定、锁定期间、到期新周期、成功清零、并发同号/异号，以及改密成功、错误原密码、同密码、格式拒绝、全部旧令牌失效和事务回滚。BCrypt 格式占位字符串不能替代真实密码验证证据。

自动化账号使用运行期专属夹具、真实 BCrypt 和既有独立测试库，不写开发库，不执行真实账号种子。测试命令、隔离清理及Phase 3历史结果和Phase 3.1当前结果的区别见 [认证 API 测试](AUTH_API_TESTS.md)及相应阶段报告。fieldErrors契约已确认并实施；本轮真实MySQL完整后端298项通过且无跳过，包含全部原有密码、锁定、JWT和数据库回归，package成功。两库结构与数据摘要起止一致。完成后待审核并停止，不进入Phase 4；没有短信、邮箱、找回密码、第三方登录、刷新令牌或设备管理。
